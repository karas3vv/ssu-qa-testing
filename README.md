# UI-автотесты «Гипермаркет ДОМ»

Целевой сайт — каталог линолеума gipermarketdom.ru с выбранными цветами «белый» и «серый». Адрес с фильтрами находится в core/config.py. За основу взяты кейсы из индивидуальной работы и техническое задание по автоматизации тестирования.

## Основной сайт

По умолчанию pytest открывает gipermarketdom.ru. В видимом Chromium магазин открыл каталог. В отдельном фоновом прогоне сервер предъявил CAPTCHA. HEADED=1 открывает окно теста для ручного прохождения при необходимости. Каждый тест получает отдельную сессию. Вход во встроенной вкладке Codex относится только к этой вкладке.

## Демонстрация

Требуются Python 3.10+, Node.js с npm, Java для Allure CLI. Из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
npm ci
TARGET=demo HEADED=1 .venv/bin/python -m pytest
npm run report
```

Откройте allure-report/index.html. В режиме TARGET=demo данные подставляются автоматически. Каждый запуск pytest очищает выбранный каталог результатов. HTML-отчёты и исходные результаты Allure хранятся локально. Git исключает папки `*-report` и `*-results`, локальные зависимости и файлы окружения.

### Показ в видимом Chromium

Запускайте из корня проекта в обычном терминале. На этом компьютере установлен Chromium по пути ниже. При установке браузера через `playwright install chromium` переменную `BROWSER_BINARY` можно убрать.

```sh
export BROWSER_BINARY="$HOME/.cache/ms-playwright/chromium-1243/chrome-linux64/chrome"
TARGET=store HEADED=1 SLOW_MO_MS=700 .venv/bin/python -m pytest -q \
  autotest/test_shop.py::test_store_cart --alluredir=defense-store-results
TARGET=demo HEADED=1 SLOW_MO_MS=700 .venv/bin/python -m pytest -q \
  autotest/test_shop.py::test_order --alluredir=defense-demo-results
```

Первая команда открывает каталог магазина, карточку линолеума и гостевую корзину. Если появится CAPTCHA, пройдите её в открытом Chromium. Вторая команда показывает полный заказ на локальном учебном стенде. Настройка `SLOW_MO_MS` замедляет действия Playwright в миллисекундах. После завершения теста окно закрывается, а pytest выводит результат в терминал.

### Показ оформления на защите

Начните с пустой корзины или используйте уже добавленный артикул 1203021011 площадью 3 м² и длиной 1 пог. м. Если в корзине только точные дубли этой позиции, тест убирает лишние строки и проверяет итог за одну позицию. Если среди строк есть другой товар, количество или цена, тест останавливается перед удалением. Введите номер телефона или email, которым пользуется аккаунт для входа по паролю. Тест проверяет итоговую сумму и наличие кнопки оформления на форме самовывоза.

```sh
TARGET=store HEADED=1 SLOW_MO_MS=700 PROMPT_LOGIN=1 .venv/bin/python -m pytest -qs \
  autotest/test_shop.py::test_order --alluredir=defense-store-checkout-results
```

Прогон на реальном сайте завершается на форме самовывоза до отправки заказа. Для проверки создания заказа используйте учебный стенд. В нём код подтверждает заказ, сверяет его номер и повторно открывает страницу заказа для проверки состава и суммы.

После клонирования сформируйте отчёт учебного прогона командой `npm run report` из раздела «Демонстрация». Для отчёта по отдельному прогону передайте его каталог результатов команде `allure generate`, как в примере ниже.

## Кейсы и ожидаемые результаты

| ID | Данные и действие | Ожидание |
|---|---|---|
| AUTH-03 | Телефон или email аккаунта и верный пароль | В «Личных данных» совпадает соответствующее поле владельца |
| AUTH-04 | Пустой логин, непустой пароль | Браузер сообщает об обязательном поле, кабинет требует входа |
| AUTH-05 | Заполненный логин, пустой пароль | Ошибка обязательного пароля, сессия отсутствует |
| AUTH-06 | Логин существующего аккаунта, неверный пароль | Общая ошибка учётных данных, кабинет требует входа |
| AUTH-07 | Несуществующий email, непустой пароль | Общая ошибка учётных данных, кабинет требует входа |
| AUTH-FMT | Email с двумя символами @, непустой пароль | Форма сообщает об ошибке, кабинет требует входа |
| MAIN-01 | Поиск товара по артикулу 1203021011 | В выдаче есть нужный товар, открывается его карточка |
| MAIN-13 | Открыть выданный каталог и товар 1203021011 | Название, артикул и цена за м² соответствуют карточке |
| MAIN-14 | Добавить товар в гостевую корзину магазина | Артикул, площадь, длина, цена и сумма совпадают |
| E2E-01 | Войти с паролем, открыть товар, добавить его в корзину и перейти к самовывозу | На сайте проверяется форма самовывоза и сумма. На учебном стенде дополнительно проверяется номер заказа |

Шесть сценариев авторизации используют вкладку «По логину» с паролем. На реальном сайте проверялся аккаунт с номером телефона в качестве логина. На учебном стенде используется тестовый email. Для отдельного входа по звонку нужен свежий одноразовый код и доступ к номеру, поэтому этот способ исключён из набора. Для оформления заказа на учебном стенде номер получателя задан в тестовых данных. Фиксированные цены относятся к локальному набору данных.

## Запуск против магазина

```sh
TARGET=store .venv/bin/python -m pytest -k catalog_product --alluredir=store-results
```

Для AUTH-03 на сайте магазина задайте TEST_LOGIN и TEST_PASSWORD. В TEST_LOGIN укажите номер или email, с которым ваш аккаунт входит по паролю. После входа тест открывает «Личные данные» и сверяет соответствующее поле. Для AUTH-06 достаточно TEST_LOGIN существующего аккаунта. Тест сам генерирует неверный пароль. Без нужных данных проверки получают skipped. BASE_URL задаёт адрес совместимого стенда.

Чтобы запустить оба парольных сценария за один раз, включите скрытый ввод в терминале. Если требуется, задайте BROWSER_BINARY как в разделе «Показ в видимом Chromium».

```sh
TARGET=store HEADED=1 PROMPT_LOGIN=1 .venv/bin/python -m pytest -qs \
  autotest/test_shop.py::test_email \
  'autotest/test_shop.py::test_rejection[AUTH-06-wrong-password]' \
  --alluredir=password-store-results
```

Введите логин и пароль по очереди. Если сайт принимает номер в поле логина, введите номер в привычном формате. Символы на экране не отображаются. Playwright заполнит форму магазина. Для проверки отказа тест использует тот же логин и автоматически сгенерированный неверный пароль. Значения хранятся в памяти процесса до конца прогона. Если браузер покажет CAPTCHA, пройдите её вручную.

Для прогона всего набора уберите пути к отдельным тестам. Подготовьте корзину для сквозного сценария по инструкции в разделе «Показ оформления на защите».

```sh
TARGET=store HEADED=1 SLOW_MO_MS=700 PROMPT_LOGIN=1 \
  .venv/bin/python -m pytest -qs --alluredir=password-only-store-results
./node_modules/.bin/allure generate password-only-store-results --clean --single-file -o password-only-store-report
```

Отчёт открывается из password-only-store-report/index.html. На учебном стенде данные подставляются автоматически.

На сайте магазина MAIN-14 проверяет гостевую корзину, площадь, длину, цену и сумму. В режиме store E2E открывает товар по артикулу из выданного каталога и доходит до формы самовывоза с корректной суммой. Отдельный MAIN-01 проверяет поисковый виджет.

## Устройство проекта

core/config.py читает параметры среды. core/runner.py управляет изолированными браузерными контекстами, журналом и Allure. ui/pages.py содержит BaseElement, объекты страниц и локаторы. autotest/test_shop.py содержит сценарии и параметры. demo/server.py реализует учебные формы, сессии и заказы.

BROWSER принимает chromium, firefox или webkit. Установите выбранный браузер через playwright install. При необходимости BROWSER_BINARY указывает исполняемый файл. TIMEOUT_MS управляет ожиданиями. LOG_LEVEL принимает DEBUG, INFO, WARNING (или WARN), ERROR. Логируются названия операций и полей. Значения полей, сетевые заголовки и cookies в журнал не передаются. На падении прикладывается снимок страницы со скрытым текстом и полями или причина его отсутствия. Локаторы используют ID полей, data-local-code, атрибуты name и контейнер формы. У товара есть ссылки на фото и название, поэтому ссылка уточняется по видимому тексту.

## Проверка на действующем сайте

В авторизованной вкладке проверены переход в кабинет, добавление трёхметрового варианта, строка корзины и переход «Оформить самовывоз». Форма отображает получателя, телефон, варианты оплаты и сумму. Финальная кнопка отправляет реальный заказ в сборку. Сведения из уже открытой вкладки браузера автоматически в процесс pytest не передаются.

Для MAIN-14 используется отдельная гостевая корзина. Цена берётся с карточки во время выполнения. При длине 1 м.п. и ширине 3 м ожидаемая сумма равна цене за м², умноженной на 3. Для AUTH-04 и AUTH-05 достаточно заполнить второе поле синтаксически допустимым значением. Для AUTH-07 генерируется адрес домена .invalid.

Для независимых прогонов можно передавать --alluredir с разными каталогами. Тайм-аут загрузки страниц задаёт NAV_TIMEOUT_MS, тайм-аут действий — TIMEOUT_MS.
